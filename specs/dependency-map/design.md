# Design — Dependency Map (generated script ↔ asset provenance)

> Satisfies R159–R164. One new stdlib-Python tool `tools/asset_map.py` + its generated output
> `docs/technical/asset-map.md`, plus prose in `docs/technical/code-map.md` and pointers in
> CLAUDE.md / spec-workflow.md. No runtime code, no game logic, no server/shared/client change
> beyond optional provenance comments. Logged as TD-051.

---

## Why generated, not hand-written (the core decision)

Three candidate shapes were weighed:

| Approach | "What is wired" | "Why it's wired" | Drift risk |
|---|---|---|---|
| Inline comments only | scattered, a producer can't know all consumers | good | high — silent |
| Hand-written doc | one place, but manual | good | **high — and stale = misleading** |
| **Generated map + `--check`** (chosen) | complete, always current | — | **none (guarded)** |

A dependency doc is only useful if a session can *trust* it without re-verifying; the moment it can
drift, the session must re-scour anyway and the doc bought nothing. So the graph is **derived** and a
`--check` makes staleness a hard failure. Inline **provenance headers** cover the orthogonal "why",
which no scanner can infer. The two are complementary, not redundant.

## `tools/asset_map.py` — the scanner

Stdlib only (`os`, `re`, `sys`, `glob`, `argparse`, `difflib`). Repo root is derived from the script's
own location (`tools/` → parent). `res://` resolves to `<root>/client/`.

### Edge extraction (regex over source text)

- **GDScript** (`client/**/*.gd`):
  - `load\(\s*"(res://[^"]+)"` and `preload\(\s*"(res://[^"]+)"` → a reference from this `.gd` to the path.
  - A `.gd`/`.tscn` target is a **script/scene** edge; anything else is an **asset** edge.
- **Scenes** (`client/**/*.tscn`): `\[ext_resource[^\]]*path="(res://[^"]+)"` → scene→resource edge.
- **Generators** (`client/assets/ui/*.py`): `(?:\bA\.)?write_png\(\s*"([^"]+)"` → this `.py` **produces**
  the named file (written relative to `client/assets/ui/`, the documented CWD).

Each match keeps its `(file, lineno)` for the report and for the "unresolved" trail.

### Path resolution + templating (R160)

A captured literal may be static or a Python format string. Normalize:
- Replace `%d`, `%i`, `%s`, `%0Nd`, `%x`, and `{}` / `{name}` with `*` → a glob.
- If the glob contains `*`: `glob.glob` it under the resolved dir; each hit is a concrete edge. **Zero hits**
  on a pattern with a real prefix → record under **Dangling** (the template points nowhere).
- If it's a plain literal: the edge is that one file; if the file is absent → **Dangling**.
- A captured string that still contains a stray `"` + `+` (concatenation) or has no usable prefix after the
  regex (i.e. the path is built from a variable) can't be matched → **Unresolved dynamic**, listed verbatim
  with location (R160 AC / P93). The extractor is deliberately conservative: it only claims an edge it can
  ground in a real file.

### Model

```
producers:  asset_path -> set[generator.py]
consumers:  asset_path -> set[(consumer_file, kind)]      # kind ∈ {load, preload, ext_resource}
preloads:   gd_path    -> set[gd_path]                     # script graph
unresolved: list[(source_file, lineno, raw_string)]
on_disk:    every file under client/assets/**             # for orphan + dangling
```

### Output — `docs/technical/asset-map.md` (R159/R161/R162)

Deterministic Markdown (every set sorted). Sections:
1. **Banner** — `<!-- GENERATED by tools/asset_map.py — DO NOT EDIT. Regenerate: python3 tools/asset_map.py -->`
   + a one-line "as of `git rev-parse --short HEAD`" stamp is **omitted** (would churn every commit); instead
   a plain "regenerate after any dependency change" note keeps the file stable under `--check`.
2. **Assets** — grouped by directory; per asset: `produced-by`, `consumed-by` (with kind). The line every
   session wants: *"`crest_v1.png` — produced by `gen_heraldry.py`; consumed by `board_decor.gd` (load)."*
3. **Scripts** — per `.gd`: `loads`, `preloads`, `loaded-by`.
4. **Generators** — per `.py`: `writes`.
5. **Orphans** — `client/assets/**` files with empty producers ∧ empty consumers.
6. **Dangling** — resolvable references with no file on disk.
7. **Unresolved dynamic references** — the scanner's declared blind spots.

### Modes (R161)

- default / `--write`: regenerate and write the file.
- `--check`: build the same text in memory, `difflib` against the committed file; **exit 1** on any diff
  (print a unified diff excerpt). Wire-free, fast — the one command a fresh session runs to trust the map.
- `--selftest`: run the assert-based checks (V1–V3, V5 synthetic cases) and print `OK`; **exit 1** on
  failure. This is the spec's named test (no Vitest — Python tooling convention, mirrors `ashember.py`'s
  self-test).

## `docs/technical/code-map.md` (R163)

Fill the placeholder with the human layer the generated file can't be:
- a short "how to read `asset-map.md` + `python3 tools/asset_map.py [--check|--selftest]`",
- the standing gotchas (generators run FROM `client/assets/ui/`; brand-new PNGs need
  `godot --headless --import`; `res://` == `client/`),
- the **provenance-header** convention (below),
- links: `→ asset-map.md` (the graph), `→ dev-environment.md` (running things).

### Provenance-header convention (R163)

An **optional** top-of-file block for non-obvious wiring — the *why*, not the *what*:

```gdscript
# @consumes res://assets/ui/crest_v1.png  — heraldic crest, drawn as a popup-tracking overlay
# @why      overlay (not a child of the ScrollContainer) so it can crown OVER the clipped top edge
```
```python
# @produces crest_v1.png, board_nameplate.png  — run FROM client/assets/ui/; headless-import new files
# @why      authored at display resolution + shown 1:1 NEAREST to avoid LINEAR downscale mush (TD-050)
```

The auto map stays the source of truth for *what* is wired; the header explains *why* so the next session
doesn't reverse-engineer intent. (v1 does not parse `@why`; it is human-facing. The scanner MAY later hoist
a one-line `@why` into the asset entry — noted as future, not built now.)

## Correctness Properties

- **P92 (deterministic, R159):** stable-sorted output — same tree → byte-identical file; `--check` only
  fails on a real change.
- **P93 (no silent gaps, R160):** every extracted reference is either resolved to on-disk file(s), or listed
  under Dangling / Unresolved — the scanner never claims completeness it doesn't have.
- **P94 (containment, R164):** stdlib-only; reads `client/`+`src/`, writes only `docs/`; imported by nothing
  at runtime; mutates no asset/script/scene.

## Notes / future

- The tool scans text, not the Godot resource system — it is intentionally simple + dependency-free. It will
  not catch a resource loaded purely by a runtime-built string; those are exactly what the Unresolved section
  exists to flag.
- A pre-commit hook or CI step calling `--check` is a natural follow-up (keeps the map honest automatically)
  but is **out of scope** for v1 — the manual `--check` command satisfies R161.
